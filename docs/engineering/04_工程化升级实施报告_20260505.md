# MediGenius 工程化升级实施报告（2026-05-05）

## 1. 本次实施范围

本次没有进行云端部署，重点完成本地可运行的后端工程化基础改造：

- 安全登录：从仅传 `user_id` 改为密码登录、密码哈希、签名 access token。
- Redis 基础设施：新增可选 Redis 客户端，Redis 不可用时自动降级到进程内存储。
- 语义缓存：新增低风险医学问答语义缓存框架，key 不保存完整 query。
- 任务队列：新增本地 worker-pool 任务队列和 job 状态查询接口，为后续 Celery/RQ/Kafka 替换留接口。
- Agent 稳定性：聊天工作流增加并发上限、超时和降级响应。
- 健康检查：新增 `/healthz` 和 `/readyz`。
- 前端登录：登录表单新增密码，后续请求携带 Bearer token。

## 2. 主要后端改动

### 2.1 安全认证

新增文件：

- `backend/app/models/user.py`
- `backend/app/services/auth_service.py`

改动内容：

- 新增 `users` 表，按 `tenant_id + user_id` 唯一约束用户。
- 密码使用 `PBKDF2-HMAC-SHA256` 加盐哈希保存，默认迭代次数 `310000`。
- 登录成功签发 HMAC 签名 access token。
- `/api/v1/auth/login` 改为接收 `user_id + password + tenant_id`。
- `/api/v1/auth/me` 支持通过 `Authorization: Bearer <token>` 解析身份。
- `/api/v1/auth/logout` 清理会话身份。
- 登录接口增加固定窗口限流。

注意：

- `AUTH_AUTO_CREATE_USERS=true` 适合当前开发阶段，生产环境建议改为 `false`，改用后台创建用户或注册审核流程。
- 当前前端将 access token 放在 `localStorage`，后续生产化建议升级为 `HttpOnly + Secure + SameSite` Cookie + refresh token 轮换。

### 2.2 Redis 与限流

新增文件：

- `backend/app/services/redis_service.py`
- `backend/app/services/rate_limit_service.py`

改动内容：

- 新增 `REDIS_ENABLED`、`REDIS_URL`、`REDIS_SOCKET_TIMEOUT_SECONDS` 配置。
- Redis 连接失败或未启用时使用进程内 fallback，保证本地开发不依赖 Redis。
- 新增用户/IP 维度固定窗口限流能力。
- 聊天接口和登录接口均接入限流。

### 2.3 语义缓存

新增文件：

- `backend/app/services/semantic_cache_service.py`
- `backend/tests/test_semantic_cache_service.py`

Key 设计：

```text
mg:semcache:answer:chat:v1:{semantic_fingerprint}
mg:semcache:fingerprint:chat:v1:{semantic_fingerprint}
```

本次实现重点：

- 不使用完整 query 作为 Redis key。
- 从 query 中提取结构化语义信息：`intent`、`entities`、`question_type`、`negation`、`risk_level`、`prompt_version`、`rag_collection_version`。
- 对结构化语义 JSON 做稳定哈希得到 `semantic_fingerprint`。
- 仅允许 `risk_level=low` 且实体足够明确的问题进入缓存。
- 急症、检查报告、个体化用药、ECG 等风险较高问题不复用最终答案。

当前版本是规则型语义缓存框架，后续可以把 `fingerprint` 索引扩展为 Redis Vector Search。

### 2.4 任务队列

新增文件：

- `backend/app/services/task_queue_service.py`

新增接口：

```text
POST /api/v1/chat/jobs
GET  /api/v1/jobs/{job_id}
```

改动内容：

- 使用 `ThreadPoolExecutor` 实现本地 worker-pool。
- job 状态写入 Redis/fallback store。
- 支持 `queued`、`running`、`succeeded`、`failed` 状态。
- API 返回 `job_id`，后续可以平滑替换为 Celery/RQ/Kafka。

### 2.5 ChatService 稳定性

改动文件：

- `backend/app/services/chat_service.py`

改动内容：

- 同步聊天和 SSE 流式聊天都先查语义缓存。
- 未命中缓存才进入 LangGraph workflow。
- workflow 调用增加 `BoundedSemaphore` 并发上限。
- workflow 调用增加 `asyncio.wait_for` 超时控制。
- 超时或异常时返回系统降级答案，而不是让请求崩溃。
- 成功生成的低风险答案写入语义缓存。

新增配置：

```text
CHAT_MAX_CONCURRENT_WORKFLOWS=8
WORKFLOW_TIMEOUT_SECONDS=90
CHAT_RATE_LIMIT_PER_MINUTE=60
```

### 2.6 数据库与配置

改动文件：

- `backend/app/db/session.py`
- `backend/app/services/database_service.py`
- `backend/app/core/config.py`

改动内容：
